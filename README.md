# 拾图 Shitu

Windows 上的本地图片、视频、3D 模型与 AE 工程素材库。支持文件与文件夹导入、工程资源收集、缩略图浏览、模型交互预览、标签与分类、收藏、回收站、备份、Chrome 网页采集和本地图片处理。

素材保存在你选择的文件夹中。应用使用 Electron、原生 JavaScript 和 Sharp；AI 放大/抠图组件随完整安装包提供，在本机运行。

## 下载安装

从 [最新正式版本](https://github.com/MAxiangm/shitu-releases/releases/latest) 下载 `shitu-版本号-setup.exe`，适用于 Windows 10 22H2 / Windows 11 x64。安装到当前用户目录，无需管理员权限。首次启动新建素材库或选择已有素材库。

**请先手动安装 0.13.2 或更新版，以修复旧版的 GitHub 下载跳转问题。** 修复版启动约 2 秒后检查新版本，此后每 5 分钟检查一次，回到应用或恢复联网时也会检查。新版在后台下载，顶栏显示进度；下载完成后点击“重启更新”。应用保存数据、等待旧进程退出，再安装并重新启动。也可以点击顶栏“更新”手动检查。

0.13.1 及更早版本需要先手动安装一次本次修复，覆盖安装会保留独立素材库和配置。更新失败时当前版本仍可使用，修复版也提供官方下载页入口。

## 浏览器采集

在应用中打开“浏览器采集”找到扩展目录，在 Chrome 的 `chrome://extensions` 开启开发者模式并加载该目录。扩展自动连接本机拾图。支持图片和可直接下载的视频，不处理受保护或分段视频流。

0.11.1 的采集助手优先从浏览器读取图片（同源请求沿用网页会话，跨域受网站 CORS 限制且不携带 Cookie），读取失败或超过 20 MB 时再由桌面下载。开始提示仅表示任务进行中，收到明确入库回执才会显示已保存；可在扩展弹窗或桌面“浏览器采集”面板查看最终结果。采集成功通知中的“查看”会清除搜索、文件夹与格式筛选并定位素材；已在回收站的重复内容会明确说明。

桌面更新后，需要在 Chrome 扩展管理中重载采集助手，并刷新素材网页。若原来加载的是 Downloads 等其他目录的扩展，请用新版扩展文件夹替换；单独安装桌面新版不会自动更新那份扩展。

## 文件夹与子文件夹

0.14.0 支持多级文件夹。打开「文件夹」菜单，在文件夹的更多菜单中选择「新建子文件夹」，或新建时选择上级文件夹。当前文件夹下新建默认作为子文件夹，也可以选择顶层。

层级可以展开、收起；查看父文件夹会包含其所有子文件夹的素材。导入时素材加入当前选中的文件夹，详情和素材右键菜单会显示完整路径。同级名称不能重复，不同父级可有同名文件夹；移动时不能选择自身或其子文件夹作为上级。

删除文件夹只删除它及子文件夹的分类信息，素材文件保留并回到未分类。层级随素材库备份和迁移。旧平级库可直接使用；首次保存子文件夹后，索引升级为版本 2，请使用拾图 0.14.0 或更新版打开，旧版会拒绝读取以保护层级。

## 颜色标记

0.15.0 支持为素材和文件夹设置自定义颜色标记。素材可以右键选择「标记颜色」，也可以在详情面板设置；多选素材时会一起应用。点击「自定义颜色」后，可用取色器选择颜色，也可以输入 `#RRGGBB` 或 `#RGB` 色号，确认后保存。另提供八种快捷颜色。文件夹通过操作菜单中的颜色区域设置，子文件夹与内部素材的颜色独立保存。

选择「无颜色」可以清除标记。颜色只用于素材库里的识别提示，不会改变原图、视频、模型或工程内容；标记会随素材库备份和迁移。

## 视频格式与预览

0.10.9 加入本地 FFmpeg 视频解码。支持导入 DXV/DXV3（常见为 MOV 容器）、MP4、MOV、AVI、MKV、WebM、WMV、ASF、MPEG、MTS/M2TS、TS、VOB、FLV、MXF、3GP、RM/RMVB、DV 等视频文件。支持的具体视频编码取决于内置解码器，不处理 DRM 加密内容。

0.10.10 修复视频准备期间快速重开、切换后返回所触发的取消错误，同一视频的重复请求共享准备任务。

视频导入后生成 JPEG 缩略图，并读取尺寸、时长和视频编码。播放器可以直接播放的常规 MP4/WebM 会使用原文件；DXV、ProRes 等需要兼容解码的内容会在首次预览时生成本地 WebM 缓存（最长边约 1080p，VP9/Opus）。带透明通道且可解码的视频保留预览透明度。生成期间可以切换或关闭预览，过期任务会取消。

**原视频不转码覆盖。** 导出和拖出仍使用原始文件；兼容预览保存在用户配置目录的 `video-previews` 中，不上传视频。解码组件随安装包提供，无需另装播放器。首次预览大视频需要一定处理时间。

组件及许可证见 [视频运行时说明](docs/VIDEO_RUNTIME_LICENSE.md)。

## 3D 模型资产

0.11.0 支持 GLB/glTF、FBX、OBJ、STL、PLY，以及 Blender、Cinema 4D、3ds Max 原工程。把模型或项目文件夹拖入拾图，模型和找到的材质、贴图、二进制缓冲自动存成一个资源包；依赖贴图不会在画廊中重复出现。原文件保留在原处，导出和拖出都会携带整包。

GLB/glTF、FBX、OBJ、STL、PLY 可离线预览，支持旋转、缩放、平移、线框和模型动画，以及 Draco/Meshopt/KTX2 解码。Blender 工程通过本机 Blender 转为预览；C4D/Max 工程需要本机可用且已授权的对应软件。原生工程也可以附带同名 GLB/glTF/FBX/OBJ 作为预览侧车，无需启动原软件。

原生私有工程的贴图会从同目录和 `tex/textures/maps/images/materials/sourceimages` 等常见目录收集；外部引用、链接工程、专用渲染器及插件材质不能保证完整重现。导入后可查看文件数量与缺失提醒，复杂工程建议先在原软件中收集资源，再拖入整个项目文件夹。包含 3D 模型的新素材库需使用 0.11.0 或更新版打开。

完整格式说明、转换配置和许可证见 [3D 模型支持](docs/3D模型支持.md)。

## AE 工程收录与整包导出

0.12.0 支持 `.aep` 和 `.aepx`。拖入工程或项目文件夹时，拾图调用本机可用的 After Effects 独立实例，收集工程引用的图片、视频、音频、序列帧及代理素材，并将收录副本重新链接到包内素材。正在编辑的 AE 会话及源文件不变。

素材库把 AE 工程作为一份资产保存。0.13.0 起，收录后自动生成主合成封面；双击查看合成静态大图，并可切换其他合成。预览从工作区域抽取代表帧，尽量避开黑场，不生成视频。首次生成需要本机 AE，失败可重试，不影响已收录工程。

导出或从拾图拖出，会得到包含已链接工程与依赖的完整文件夹。去重同时检查原工程与依赖内容，修改素材后的工程可再次收录。预览缓存单独保存，不修改资源包。

收集需要本机安装可用的 After Effects。优先使用与原工程匹配的已安装版本，收集版本显示在工程详情中；用较新 AE 另存的副本可能需要相应版本才能打开。字体、第三方插件、专用渲染器及表达式动态加载的外部文件不能保证自动收集，缺失资源会保留提示。加入 AE 工程的素材库需用 0.12.0 或更新版打开。详见 [AE 工程打包](docs/AE工程打包.md)。

## 本地开发

需要 Windows x64、Node.js 24 和 7-Zip。公开仓库不存储体积较大的 Electron、Sharp 原生模块和 AI 模型；首次从固定版本的公开安装包恢复这些依赖，并校验 SHA-256：

```powershell
git clone https://github.com/MAxiangm/shitu-releases.git
cd shitu-releases
node scripts/prepare-build-resources.cjs
node scripts/start.cjs
```

如果使用已经准备好的完整开发目录，直接双击 `启动开发版.cmd` 即可。该入口使用项目内运行环境，不要求系统安装 Node.js。开发版默认使用 `.recovery/development/` 下的独立素材库和配置，不自动打开正式版的素材库。

```powershell
.\开发工具.cmd start --devtools
.\开发工具.cmd check
.\开发工具.cmd test
.\开发工具.cmd smoke
.\开发工具.cmd smoke-update
.\开发工具.cmd video-fixtures
.\开发工具.cmd smoke-video
.\开发工具.cmd smoke-model
```

`smoke-update` 使用封闭的模拟 GitHub 响应与安装器启动记录，覆盖版本检查、下载校验、界面、IPC、数据保存和退出流程；不访问网络，也不执行安装器。

`video-fixtures` 从 FFmpeg FATE 下载并校验 6 个小型 DXV/DXV3 测试样例；`smoke-video` 实际验证解码、缩略图、兼容预览和切换视频。测试样例不加入发布安装包。

`node scripts/prepare-model-test-fixtures.cjs` 下载并校验固定版本的三个模型/纹理样例；`smoke-model` 验证实际模型入库、贴图打包、封面、删除测试源后独立预览、旋转缩放及切换重开。`node scripts/smoke-model-viewer.cjs` 额外验证 FBX、Draco、KTX2、点云和外部引用阻断。所有测试库均在 `.recovery/tests`，不使用正式素材库。

修改 `src/` 后重启开发实例即可。`src/main.cjs` 是主进程入口，界面位于 `src/renderer.js`、`src/index.html` 和 `src/styles.css`；浏览器扩展位于 `extension/`。

## 构建与发布

```powershell
.\开发工具.cmd installer
.\开发工具.cmd publish --publish --notes-file release-notes.md
```

构建生成便携版、Windows 安装包和 `shitu-update.json`。上述发布命令会在完整附件上传并校验后公开正式最新版，并验证匿名访问；只创建草稿时省略 `--publish`。也可以使用 `npm run release:github` 正式发布、`npm run release:draft` 创建草稿。需要已经登录的 GitHub CLI 或当前进程中的 `GH_TOKEN`，客户端不包含发布令牌。本地生成安装包和创建草稿均不等于已经发布给用户。

后续版本也可修改 `package.json` 的版本号、提交源码，然后推送对应 `v版本号` 标签，由 GitHub Actions 在 Windows 上测试、构建并发布。固定引导包只提供二进制依赖，构建始终使用当前提交的应用源码。详见 [GitHub 发布说明](docs/GitHub发布.md)。

更新来源配置在 `update-config.json`。客户端只接受该仓库的正式版本，校验安装包大小和 SHA-256；执行安装前再次校验文件。预发布、旧版本、不完整附件、非 GitHub 下载地址和校验失败的文件不会被安装。

0.13.2 修复了 Electron 请求 GitHub 下载跳转失败的问题；0.13.1 及更早版本请先手动下载安装一次。之后手动检查会主动获取新元数据；启动后约 2 秒检查，后台每 5 分钟检查。恢复窗口、获得焦点和恢复联网也会触发检查，自动请求至少间隔 60 秒并跳过下载或安装过程。网络恢复由本机状态每 10 秒采样，不会每 10 秒请求 GitHub。GitHub 发布传播和网络无法保证零时延。

`npm run test:updates:live` 显式运行真实 Electron 联网检查，使用独立测试配置验证 GitHub 更新清单与安装包的受控跳转。安装包只读取 2 字节文件头后取消，不下载完整安装包或执行安装器；此命令不会在 CI 自动运行。普通更新 smoke 仍使用封闭网络模拟。

## 主要目录

| 路径 | 内容 |
| --- | --- |
| `src/` | 桌面应用、更新器和图片处理逻辑 |
| `extension/` | Chrome 采集扩展 |
| `assets/` | 应用图标与资源 |
| `scripts/` | 启动、测试辅助、构建与发布脚本 |
| `tests/` | 素材库、更新器与发布清单测试 |
| `build-resources.json` | 引导安装包的固定版本与校验值 |
| `video-runtime-manifest.json` | 视频解码组件的固定版本、来源和校验值 |
| `.github/workflows/` | Windows 发布工作流 |

`.recovery/`、`node_modules/`、`ai-runtime/`、`video-runtime/`、构建结果和个人素材库不进入 Git 历史。第三方组件许可见 `src/AI_THIRD_PARTY_NOTICES.md`、`src/ai-licenses/` 及 `docs/VIDEO_RUNTIME_LICENSE.md`。
